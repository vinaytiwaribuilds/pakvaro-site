Reference builds

Reference builds, with the evidence attached.

Self-initiated builds that show how Pakvaro engineers a workflow: the design, the failure handling, the automated tests and the run evidence. Each one states what it does, what was tested and what it does not prove.

Current reference build

Resilient lead intake in n8n

n8nWebhooksCRM handoffFailure recovery

Lead intake → validation → CRM → owner alert

Accepts a lead by webhook, validates and normalises its fields, scores it, prevents duplicate CRM records and sends the owner the result needed for follow-up.

Video comingThree-minute uncut walkthrough planned

Failure path included

A CRM outage is retried twice. A third failure creates a dead-letter record, produces an action-needed alert and returns a visible error instead of silently dropping the lead.

Acceptance evidence

  • Invalid input rejected before a write
  • Idempotency prevents duplicate records
  • Temporary CRM failure recovers on retry
  • Persistent failure reaches the dead-letter path
  • Unexpected execution failures are recorded separately
  • 5 of 5 automated tests passed against a local n8n run (evidence in the repository)

What this does not prove

The CRM, alert endpoint and dead-letter store are local mocks. The build does not establish production uptime, throughput, security, recovery time or results for a real business. A live implementation still needs the selected accounts, permissions, retention rules, monitoring and acceptance criteria.
